Stellar Wallet Kit

A TypeScript wallet-adapter prototype for connecting browser wallets, obtaining a public key, and signing Stellar transaction or Soroban authorization XDR.

Implementation status

Prototype: verify package completeness before adopting. The checked-in implementation contains the core class and browser adapters for Freighter, Albedo, and Rabet. WalletConnect is a placeholder that throws “implementation pending.” React providers/hooks, UI components, and test utilities mentioned in the repository README are not present in the current source tree.

This documentation describes the actual src/core and src/wallets implementation. The package manifest declares additional export paths; check that a published build includes those modules before importing them. There is no guarantee that every listed wallet enum has an implemented adapter.

Install and project setup

The package is named @nexastellar/wallet-kit. Its manifest currently specifies Stellar SDK and WalletConnect dependencies, and React as optional peer dependencies.

npm install @nexastellar/wallet-kit @stellar/stellar-sdk

Initialize the kit in a browser application. Wallet connections access browser-injected providers and browser local storage, so run connection code in a client-side context rather than during server-side rendering.

Quick start

// In this repository checkout:
import { WalletKit } from './src/core/WalletKit';
import { WalletType } from './src/core/types';

const kit = new WalletKit({
  network: 'testnet',
  projectName: 'Example Stellar App',
  autoConnect: false,
});

const wallets = kit.getAvailableWallets();
console.table(wallets);

const wallet = await kit.connect(WalletType.FREIGHTER);
console.log('Public key:', wallet.getPublicKey());

const signedXdr = await kit.signTransaction(unsignedTransaction.toXDR());
// Submit using your chosen Horizon or Soroban RPC flow.
// The kit's submitTransaction method submits to Horizon.

unsignedTransaction is an application-built Stellar SDK transaction; this kit does not construct transactions. The example uses checkout-relative source imports. The package root entrypoint is not included in the current source tree, so these imports are not a supported published-package path until package exports are completed and verified.

connect returns the adapter instance. It exposes getPublicKey(), getNetwork(), and signTransaction(xdr).

Configuration

OptionTypeBehavior
network'mainnet' | 'testnet'Required. Selects the network passphrase and default Horizon/Soroban URLs.
projectNamestringRequired. Used in WalletConnect metadata.
projectIcon, projectUrlstring (optional)WalletConnect metadata fields; default to empty strings.
autoConnectbooleanDefaults to true. Attempts to restore a saved provider choice in a browser.
autoApprovebooleanDefaults to false; currently stored but not used by the adapters.
walletConnectProjectIdstringOptional config value, but WalletConnect connect/sign functionality is not implemented.
horizonUrl, sorobanRpcUrlstringOptional endpoint overrides. Horizon is used by account loading and transaction submission; Soroban RPC URL is not currently used for requests.

Defaults are https://horizon.stellar.org and https://horizon-testnet.stellar.org, and the analogous Soroban RPC URLs. switchNetwork resets endpoints to defaults; it does not preserve custom endpoint overrides.

Core API reference

MethodResult / notes
new WalletKit(config)Creates a kit and a Horizon server; may start asynchronous restoration when autoConnect is true.
getAvailableWallets()Returns entries with type, name, icon, and available. Availability does not imply that a provider operation is implemented.
isWalletAvailable(type)Checks whether the adapter reports its provider available.
connect(type)Disconnects the current adapter, connects the requested provider, stores its type in local storage, emits connected, and returns the adapter.
disconnect(), getWallet(), isConnected()Disconnect, access the current adapter, or check adapter connection state.
signTransaction(xdr)Signs transaction envelope XDR with the connected adapter; rejects if no adapter is connected.
signAuthEntry(entry)Signs a Soroban authorization entry where the selected adapter supports it.
submitTransaction(xdr)Submits XDR to the configured Horizon server and returns { hash, ledger, success }; emits success/error events.
loadAccount(publicKey?)Loads an account from Horizon for the supplied key or connected wallet key.
getNetwork(), getNetworkPassphrase(), switchNetwork(network)Read/switch network context. Switching disconnects the current adapter.
on(event, callback), off(event, callback)Register or remove callbacks for the event names listed below.

Although a few declarations in the README differ, the current class is the source of truth. It does not expose a useWallet hook, balance hook, transaction hook, or built-in transaction builder.

Wallet adapter support

AdapterAvailability checkImplemented behavior
Freighterwindow.freighter existsConnect, transaction signing, and auth-entry signing through the injected provider.
Albedowindow.albedo existsPublic-key connection and transaction signing. Auth-entry signing throws unsupported.
Rabetwindow.rabet existsConnect, transaction signing, and auth-entry signing through the injected provider.
WalletConnectAlways reports availablePlaceholder; connect and signing methods throw “implementation pending.”

Provider APIs and browser extension versions can change. Test the exact adapter/provider combination your application supports. Do not infer support just from a wallet name in an enum or earlier README feature list.

Events and network behavior

Supported event names are connected, disconnected, accountChanged, networkChanged, transactionSuccess, and transactionError. The current code emits connection/disconnection, network switch, and submit success/error events. Account-change emission is not implemented.

Example subscription:

const onSuccess = (result) => console.log('Submitted:', result.hash);
kit.on('transactionSuccess', onSuccess);
// Later:
kit.off('transactionSuccess', onSuccess);

Connection type is stored under nexastellar_wallet_type in browser local storage. This stores a provider choice, not a private key. The kit does not custody keys.

Errors and safety

  • Check isWalletAvailable, then catch provider connection errors (for example, user rejection or a missing extension).
  • Never treat wallet availability as proof that a wallet is connected; call isConnected().
  • Review transaction XDR, network, destination, amount, and fees before requesting a signature. A signature authorizes the transaction; this library does not validate application intent.
  • Handle Horizon submission failures explicitly. A successful signature does not mean that a transaction was accepted by the network.
  • Do not use the incomplete WalletConnect adapter or unsupported UI/React imports in production.
